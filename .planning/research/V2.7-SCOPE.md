**Written:** 2026-09-16, against the live tree at `e04966e` (`main`), the day the
milestone opened. **Opened by:** operator direction, after a rendered smoke test
(2026-09-11) that the operator and the orchestrator both judged well below the
standard. **Phases:** 31–34. **Branch:** `gsd/v2.7.0-figure-pipeline`.
**Ships as:** tag `v2.7.0`.

Binding constraints carried unchanged: **D-01** (stdlib gate path), **D-02**
(gates adjudicate declarations and hermetic artifacts, never compute), **D-05**
(citation + reference value per minted check), **D-06** (additive codes only;
live catalogue **279** at open), **D-13** (deferred items promote on evidence,

**v2.7-01** (a figure-quality milestone opens only on a rendered, viewed miss)
and **v2.7-02** (quality is a property of code the agent *calls*).

This document is the scope the loop re-verifies before planning. It is not a plan.

## 1. What is being built, and why now

### 1.1 The measured miss

On 2026-09-11 a smoke test rendered nine charts — one per relationship family
except geographic — through the shipped v2.4 stack exactly as an analyst would:
`plt.style.use("styles/dsx-urban.mplstyle")`, the marks the cookbook names, and
`finalise_figure(fig, title=…, source=…)` as the cookbook models it. Seeded
random data, no `dsx seal`, no gate, no critic. The question was only: *does the
house style produce good output when used as documented?*

Every one of the nine PNG files was opened and read. The findings, attributed to
the tooling rather than to the test author, because the cookbook models exactly
the minimal call the author used:

| # | Chart | Defect observed |
|---|---|---|
| 01 | line, change over time | Title clipped at canvas edge; "East"/"North" end labels overlap; no units; the title claims "overtook in Q3" and nothing marks Q3; all three series equally saturated |
| 02 | bar, magnitude | Title clipped; **unsorted and vertical**, against this project's own documented default (horizontal, sorted by value); no units |
| 03 | histogram | No units on either axis; otherwise sound |
| 04 | scatter | No units; no fitted reference or annotation |
| 05 | bump, ranking | Title fits; **rank axis shows 1.5, 2.5, 3.5** — a categorical quantity on a continuous scale; end labels run past the canvas |
| 06 | pie, part-to-whole | Title clipped; four slices (within the five-slice rule); no values on slices |
| 07 | diverging bar, deviation | Title clipped; no units; category order is source order, not magnitude |
| 08 | Sankey, flow | matplotlib's built-in arrow diagram — not a publishable flow ribbon at any polish level |
| 09 | error bars, uncertainty | Title clipped; **five categories plotted on a numeric x-axis** with ticks at 0.0 … 4.0 in 0.5 steps; no units; the zero reference line is correct and good |

Five of nine titles clipped. Zero of nine carried units anywhere. Zero carried an
annotation. Zero used emphasis. Two plotted categorical quantities on continuous
axes. **All nine would pass the spec-level gate**, because the gate reads
`ANALYSIS-SPEC.yaml`, not the picture.

The nine SVG/PNG pairs and the generating script are preserved and become Phase 33
evidence fixtures.

### 1.2 Why the stack produces this

Four verified causes, each a specific line in the live tree:

1. **No resolution to one mark.** `dsx/input_types.py::permitted()` (lines 76–104)
   ends `return sorted(allowed)` — an *alphabetical* admissible set.
   `dsx charts IT005 --relationship comparison` returns
   `bar, bullet, dot_plot, horizontal_bar`. The rule "comparison across
   categories → horizontal bar, sorted by value" exists only as prose in
   `references/chart-selection.md`; `references/chart-catalog.md` contains zero
   occurrences of "default" or "preferred". An unattended agent picks by
   plausibility, and alphabetical order puts `bar` first.

2. **No renderer — the helper stamps, it does not lay out.**
   `templates/dsx_plotstyle.py::finalise_figure()` (162 lines total) calls
   `fig.suptitle(...)` and two `fig.text(...)` at fixed figure coordinates. It
   reserves no space, measures no width, wraps nothing. matplotlib is correctly
   FORBIDDEN on the gate path (`tests/test_gate_path_hermetic.py`, D-P23-03) —
   but the off-path half that *produces* the figure was never built, so the
   agent writes plotting code freehand.

3. **Checks that pass on omission.** `dsx/checks/viz.py::_check_ordering()`
   (lines 514–534) returns silently when `category_order` is absent — only an
   explicit `alphabetical` / `arbitrary` / `source_order` fires `DSX-VIZ-080`.
   `DSX-VIZ-061` asks whether units are *declared*, never whether they are
   *drawn*. Omission is the cheapest path through the gate.

4. **Nobody looks at the picture.** `agents/dsx-viz-critic.md` contains no
   instruction to open a PNG or SVG (grep for `png|svg|render|image`: no match).
   `skills/dsx-visualize/SKILL.md` (77 lines) never says sort, subtitle, units or
   annotate, and never mentions `dsx charts`. `references/chart-snippets.md`
   across its eleven sections contains zero `set_ylabel`, zero `subtitle=`, zero
   `figsize`, zero `note=`, zero `annotate`.

### 1.3 The shape of the answer

```
data + question
  → classify        EXISTS   dsx vocab / dsx charts (40 input types, 11 relationships)
  → RESOLVE         Phase 31 one mark + render defaults, a tested table
  → RENDER          Phase 32 figure built from the declaration by a layout engine
  → seal            EXISTS   save_deterministic + dsx seal
  → PIXEL CHECK     Phase 33 predicates over the sealed SVG + goldens
  → gate            EXISTS   spec-level, unchanged
  → critic          Phase 34 rewired to open the picture
```

Phases 31–33 build the three missing stages; Phase 34 makes every caller use them
and re-baselines calibration.

## 3. Phase content

### Phase 31 — Deterministic mark resolver

**Goal.** `dsx charts` answers "which one" as well as "which are admissible",
from a declared data signature, deterministically, with the reasoning inspectable.

**Content.**
- A resolver table keyed on: input type (or coarse family), relationship,
  category count, longest category label length, series count, has-time,
  has-interval. Output: one mark plus its render defaults — orientation, sort
  order, baseline rule, label mode (direct / legend / none), emphasis mode
  (hero / uniform), and the uncertainty mark where one applies.
- `dsx charts <shape> --relationship <rel> --resolve` printing the chosen mark,
  the defaults, and the rule row that produced it. The existing admissible-set
  behaviour is untouched (additive, D-06 in spirit).
- Every row carries a source. Candidates already in the tree or in hand:
  `references/chart-selection.md`'s relationship table (this project's own,
  already cited); Cleveland & McGill's six tied ranks (already in the tree, and
  already corrected once — six ranks with ties, **not** a strict seven);
  Wilke §5.6 for `error_bars` as the uncertainty default (already the skill's
  stated default); the operator's Chart_Audit_Framework branch `c69dbf3` for the
  card thresholds ("labels long or more than ~8–10 categories → horizontal") and
  the ranking rule (input-type exactness → function → fewer failure modes).
- One test per row. A property test that the resolver is total over the declared
  vocabulary (every (input type × relationship) pair that `permitted()` answers
  non-empty must resolve), and deterministic (same inputs → same output).

**Mints:** none expected. This is a lookup, not a check. If a resolver
disagreement needs to *block*, that is a separate D-06 decision in Phase 33.

**Open question for planning:** whether the resolver lives in `dsx/` (stdlib, on
the gate path, read by `dsx charts`) or beside the renderer off-path. Preference:
**in `dsx/`** — it is pure stdlib table lookup, it is already what `dsx charts`
does, and keeping it on-path lets the pixel check compare declared against
resolved later. It must not import matplotlib.

### Phase 32 — The renderer

**Goal.** A figure is built from its declaration by code the analyst calls, not
written freehand — so the layout defects of the smoke test become impossible
rather than discouraged.

**Content.**
- `render(spec, data, *, style=…) -> Figure` in `templates/` (off the gate path,
  beside `dsx_plotstyle.py`, never imported by any `GATE_PROFILES` module).
- **Layout engine:** three named canvases (a BBC-style 640×450 default, a wide
  variant, a small-multiple variant); reserved bands for title, subtitle, plot
  and footer; title wrapped by *measured* width (the defect behind five of nine);
  footer carrying source left and an optional note right.
- **Mandatory by signature:** `units` and `subtitle` join `source` as
  keyword-only parameters with no default, so omission is a `TypeError` at call
  binding. This is the existing `source=` pattern (the signature-level mirror of
  `DSX-VIZ-062`) extended to the two things every one of the nine charts lacked.
- **Correct by construction:** categorical axes get categorical ticks (kills the
  0.5-step rank and category axes of charts 05 and 09); comparison bars sort by
  value and go horizontal when the resolver says so; zero baselines on bar and
  area; thousands / percent / currency formatters; direct labels with collision
  pushing; hero-series emphasis with the rest greyed.
- **Determinism preserved:** the GA-3 recipe is unchanged and `save_deterministic`
  remains the writer; `dsx seal` remains the single hashing authority (GA-2). A
  double-render hash-equality test covers every rendered reference figure.
- **The Sankey leaves the representative set.** matplotlib's built-in is an arrow
  diagram, not a flow ribbon. Either a real ribbon implementation lands here or
  `flow` resolves to `funnel` and the catalogue row is marked reference-only.
  Recommendation: **drop to reference-only** this milestone — a ribbon
  implementation is its own body of work and nothing in the portfolio needs it.

**Licence gate before any modelling:** the BBC `bbplot` cookbook copy in the
operator's reference library carries **no licence file**. Its `finalise_plot`
contract (640×450, title 28 / subtitle 22 / axis 18, `#222222`, left-aligned
title and subtitle, footer with source left) may be used as a *described
contract* — our own implementation, our own numbers re-derived — only after the
upstream licence is read first-hand. If it cannot be read, the band layout is
derived from the Economist and 538 rules instead, which are documented in local
article copies as descriptions rather than code. The same standing applies as
HQ-27/HQ-33 established for citations and palettes.

**Mints:** none. The renderer is a producer.

### Phase 33 — The pixel check

**Goal.** The rendered artifact is checked, so "the gate passed" and "the chart
is good" stop being independent.

**Content.**
- Stdlib predicates over the sealed SVG (parsed as XML — no matplotlib, no
  third-party dependency, D-01 intact): nothing clipped beyond the canvas box;
  no two text elements overlapping; a subtitle element present; a unit token
  present in the subtitle or an axis label; tick labels not colliding.
- The observable conditions come from the operator's Chart_Audit_Framework
  branch `c69dbf3`, `rules/scoring-anchors.md` — Visual Design capped at 3 when
  "labels/marks clipped or colliding", capped at 5 when "legend is the sole
  decoder for >6 categories", floor 8 only when "nothing clipped/colliding,
  ≤2 non-redundant encoding channels, direct labels where the form permits".
  Cite by commit, never as `main` (`main` holds only the superseded prototype).
- **The nine smoke-test charts become fixtures**: the measured miss, with a
  before/after pair once the renderer produces them. Golden SVGs for the nine
  reference figures, diffed on change.
- **D-13 discipline applies to every mint.** Each candidate code is measured
  against the corpus at all four gate points *before* it is designed; a case the
  gate already catches closes with no mint. Each mint that ships carries a D-05
  citation and, per the v2.5-01 rule, a known-bad fixture naming it as target in
  the same commit.

**Mints:** expected but not promised. Plausible candidates — title clipped,
labels colliding, units absent from the artifact — each entry-conditioned.
Catalogue arithmetic is verified additively from 279.

### Phase 34 — Rewiring and calibration (terminal)

**Goal.** Every caller uses the pipeline, and the calibration numbers are
re-baselined against the changed surface.

**Content.**
- `references/chart-snippets.md` rewritten: every snippet calls `render(...)`,
  passes units and subtitle, and shows one annotation. The routing test
  (`tests/test_snippet_catalog_routing.py`) extended so no snippet may hand-roll
  what the renderer owns.
- `skills/dsx-visualize/SKILL.md`: the method becomes resolve → render → seal →
  check, naming `dsx charts --resolve` explicitly.
- `agents/dsx-viz-critic.md`: a step that **opens the rendered PNG** and judges
  what a predicate cannot, after the pixel check is clean.
- Calibration re-baseline: catch rate over the known-bad corpus, false-positive
  rate over the good-control corpus with its one-sided bound stated, the new
  figure cases classified, docs re-pinned to the live corpus by the existing
  agreement test.

**Mints:** zero (terminal phase, by the house pattern of Phases 12 / 20 / 30).

## 4. Ordering and contingency

31 → 32 → 33 → 34 is a hard chain: the renderer consumes the resolver's
defaults, the pixel check needs rendered artifacts to check, and the rewiring
needs all three. No wave parallelism across phases; within Phase 32 the layout
engine and the mark-specific builders can be split into parallel plans.

**Contingency.** If the BBC licence cannot be read, Phase 32 loses its cleanest
band-layout source and derives the bands from the Economist/538 descriptions plus
our own measurement — a smaller, slower path, not a blocker. If Phase 33's
candidate checks all measure as already-caught, the phase closes with zero mints
and its golden fixtures, which is a valid D-13 outcome and must not be talked
into a mint. If the resolver turns out to need a judgement the table cannot make,
the honest answer is to narrow the table's domain and say which cases stay
agent-judged — never to invent a rule with no source.

## 5. Critique register

A sceptical reader will ask these; the answers belong in the record before the
work starts.

**"You already shipped Visual Excellence. Why again?"** v2.4 shipped the
vocabulary, the gate, the style layer and the determinism recipe — all of which
hold and none of which are being redone. What it did not ship is the off-path
producer. The milestone name is different on purpose: v2.4 was excellence in the
*vocabulary and gate*; v2.7 is the *pipeline*.

**"Determinism tests were green. How was this missed?"** Because determinism
tests prove the bytes match across renders, and nobody had rendered a chart and
looked at it. The orchestrator asserted "high-quality" from the tests and was
wrong; decision **v2.7-01** exists to make that a rule rather than a memory.

**"Is this promotion on an estimate, which D-13 forbids?"** No. Nine charts were
rendered, opened and read, with defect counts per chart. That is a measurement.
The evidence is preserved as fixtures.

**"Is a renderer scope creep for a gate project?"** The renderer is analyst-side,
exactly where `dsx_plotstyle.py` already lives, and is forbidden on the gate path
by the same test that forbids matplotlib there today. The gate keeps reading
declarations and hermetic artifacts. What changes is that the artifact it reads
is now produced by tested code.

**"Why not just improve the cookbook prose?"** Because the smoke test *followed*
the cookbook. Prose is what a language model applies freehand, and freehand
application is what produced nine average charts. Decision **v2.7-02**.

**"Does the pixel check break D-01?"** No. It parses the sealed SVG as XML with
the standard library. It imports no matplotlib and reads no live data.

**"Why is the good-control corpus not being grown first?"** It is a real
weakness (15 specs, one-sided 95% bound ≈0.181 on 0/15) and it stays a v2.8
candidate with its entry condition unchanged. It lost on precedence, not on
merit: the figure miss is measured and visible to a portfolio reader.

## 6. Explicitly out of scope

- **A gate that renders.** The pixel check reads the sealed SVG; matplotlib
  never enters the gate path.
- **Imitating vendor identity.** General chart quality comparable to
  FiveThirtyEight / Economist / BBC output is the target; typefaces, logos,
  proprietary palettes and bespoke editorial pieces are not. Econ Sans stays
  unvendored (Lato under SIL OFL remains the stand-in), `ggthemes` (GPL) and
  `RDeconomist` (GPL-3) stay unread for code, the unlicensed Economist style
  guides stay cited-never-copied.
- **Interactive or web output.** SVG and PNG only; no plotly, no HTML.
- **Geographic marks.** `choropleth` and friends need a geo dependency; the
  resolver may name them, the renderer does not build them this milestone.
- **A Sankey ribbon implementation.** See Phase 32 — dropped to reference-only.
- **The v2.8 candidates**, every entry condition unchanged: `SEED-001`
  E-27 … E-31, `SEED-002`'s `parse_health` residue, `SEED-003`, `SEED-004`,
  good-control corpus growth, brief §6.5 items 1–6.
- **Two sources not read**, and therefore not cited anywhere in this milestone:
  the Tableau 538 election-chart article and Tim van Schaick's Economist article
  (both HTTP 403, no local copy). If a rule from either is wanted, it must be
  fetched and read first.
